# 인수인계: 리서치 → 숏츠 영상 자동화

최종 갱신: 2026-11-25 (2단계)

## 목표

리서치 자료(논문·기사·리포트)를 넣으면 아래 과정을 거쳐 60초 안팎의 세로 영상(1080×1920)이 나오게 한다.

```
원문 → 분석 → 관점 해석 → 스토리보드·대본 → 더빙 → 모션 그래픽 → 영상
```

이 과정은 한 번 수작업(AI와 대화하며)으로 끝까지 해 봤다. 논문 『Organizing Intelligence』(Google DeepMind, arXiv:2611.05417)를 소재로 해설 문서, 요약본, 발표 장표, 스토리보드, 더빙 영상(가로 1920×1080, 약 2분 40초)을 만들었다. 그 원형 프로젝트는 비공개 위치에 있고, 경로는 `.local/REFERENCES.md`에 적어 둔다.

## 확정한 사항

| 항목 | 결정 |
|---|---|
| 대본 쪽 LLM | **Gemini**: 분석 → 관점 → 스토리보드·대본. 출력은 **JSON Schema(Pydantic) 구조화 출력**으로 받는다 |
| 영상 쪽 LLM | **Claude Code 헤드리스(`claude -p`)**: 장면 코드를 **매번 새로 작성** → 스틸 렌더링으로 확인 → 수정을 반복 |
| 영상 프레임워크 | **Remotion**(React). Claude Code에 **Remotion 공식 Agent Skills**(`npx skills add remotion-dev/skills`) 설치 |
| 더빙 | **Typecast API**. 목소리 서현(`tc_69f2e455ea79fd197aa0476f`), 모델 `ssfm-v30`, 속도 0.9 |
| 자막·싱크 | Typecast **단어별 타임스탬프**(`/v1/text-to-speech/with-timestamps`)로 단어 단위 강조 자막과 화면 전환 시점을 맞춘다 |
| 관점 | 회사 관점. 관점 가이드·브랜딩 자료는 **레포 공개 여부를 정한 뒤** 추가한다 |
| 입력 소스 | 구성원에게 모은 자료를 나중에 추가한다 |
| 검수 | 스토리보드 단계에서 사람이 승인한 뒤 렌더링. mp4는 레포에 커밋하지 않는다 |
| 업로드 | 당분간 수동. 올릴 때 AI 생성 표시를 켠다 |

  - 실행: `python -m shorts.pipeline --source <PDF·텍스트·웹 주소>` → `.local/runs/<시각-제목>/`에 `source/analysis/perspective/storyboard.json`, `verify.json`, `review.md`
  - 뒷단계만 다시: `--run-dir <폴더> --from storyboard` (앞 단계 결과를 다시 쓰므로 Gemini 호출이 줄어든다)
  - 관점 가이드: `.local/perspective.md`(git 제외). 없으면 중립 해설. 서식은 `shorts/perspective.example.md`
  - 검사기(`verify.py`): 인용이 원문에 그대로 있는지, 화면 숫자가 원문 숫자와 같은지, 예시값·"우리 해석" 표시, 내레이션의 숫자·영문, 설정이 다른 숫자 섞임, 예상 길이. 상대 비교 claim을 쓴 장면은 "사람 확인"으로 남긴다
  - 길이 추정은 초당 6.3음절(속도 0.9 가정)이다. 3단계에서 실제 음성 길이로 다듬는다
  - 공개 논문(arXiv 2303.10130)으로 실제 Gemini 실행을 세 번 하며 프롬프트를 다듬었다: 단서 표현(could·weakly) 유지, 상관관계를 수준·인과로 바꾸지 않기, 원문 한계를 영상에 넣되 원문보다 세게 쓰지 않기, 숫자는 조건과 함께, hook은 소개 대신 숫자·질문으로, closing에는 해석을 넣지 않기. 검사기는 범위 값("47 and 56%")을 숫자마다 대조한다
  - 실행마다 결과가 조금씩 달라서 단서가 빠지거나 비교 대상이 생략되는 일이 여전히 가끔 있다. 기계 검사를 통과해도 review.md의 "사람 확인" 항목은 꼭 읽는다
  - PDF 메타데이터 때문에 제목이 "WORKING PAPER"처럼 잡힐 수 있다(`sources.py`, 아직 안 고침)

## 원형 작업에서 배운 것

**정확성**

AI가 만든 요약·장면 문구에서 원문과 다른 표현이 여러 번 나왔다. 사람의 원문 대조가 반드시 필요하다.
- "조정자의 가치가 커진다": 원문은 *전문가보다 상대적으로* 더 받는다는 뜻이고, 절대 임금은 떨어졌다.
- "혼자서는 가장 못하는 사람이 가장 많이 번다": 원문에서 조정자 2.41, 전문가 4.15라 틀린 표현이었다.
- 초역량 단계에서 전문가를 실업처럼 그렸다: 원문은 전문가가 틈새시장으로 이동한다고 말한다.
- 예시 수치는 설정이 다른 예시에서 가져온 것일 수 있다: 바깥 선택지 0.25와 1의 차이처럼, 같은 영상 안에서 설정이 섞이지 않게 표시한다.

**더빙과 길이**
- 장면 길이를 고정하면 말이 끝난 뒤 조용한 구간이 길어진다.
- 해결: 장면 애니메이션은 원래 타임라인 기준으로 짜고, 구간별로 늘이거나 줄여 **장면 길이를 음성 길이에 맞춘다**(시간 매핑). 말 시작 전 0.6초, 끝난 뒤 0.9초.
- 여러 단계가 있는 장면은 대본을 조각으로 나눠 각 단계가 시작될 때 말이 나오게 한다.
- 특정 단어를 화면 사건에 맞출 때 지금은 글자 수 비율로 추정한다. 타임스탬프 API로 바꿀 예정이다.
- TTS가 잘못 읽기 쉬운 표기는 대본에서 읽는 소리대로 적는다: 10배 → 열 배, 1인당 → 일인당, AGI → 에이지아이, Agent → 에이전트.

**레이아웃**
- 화면 구석의 캐릭터·말풍선이 라벨과 자주 겹친다. 장면마다 스틸 렌더링으로 겹침을 확인한다.

## Typecast API 메모

- 인증: `X-API-KEY` 헤더. 음성 합성: `POST https://api.typecast.ai/v1/text-to-speech` → wav/mp3 바이너리.
- 목소리 목록: `GET /v3/voices?model=ssfm-v30`.
- 본문 필드: `voice_id`, `text`(최대 2000자), `model`, `language: "kor"`, `prompt`, `output`
  - `prompt`: `ssfm-v30` 이상은 `{emotion_type: "smart", previous_text, next_text}`로 앞뒤 문맥을 주면 억양이 이어진다
  - `output`: `audio_tempo`, `audio_pitch`, `audio_format`
- 오류 코드: 401 키 오류, 402 크레딧 부족, 404 목소리가 해당 모델을 지원하지 않음, 429 요청 과다.
- 다시 생성할 때마다 크레딧이 든다. 일부 장면만 다시 만드는 옵션을 둔다.
